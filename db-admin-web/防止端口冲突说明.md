# 🔒 严格端口模式说明

## 📋 严格端口策略

### ✅ 新的端口策略
**从现在开始，数据库管理系统只能使用固定端口，绝不允许使用备用端口！**

- **前端端口**: 只能使用 `5173`，不允许5174、5175等备用端口
- **后端端口**: 只能使用 `8081`，不允许其他备用端口
- **冲突处理**: 如果端口被占用，系统会报错退出，不会自动切换

### 🚨 之前的问题现象
在启动数据库管理系统时，有时会发现服务运行在5174端口而不是配置的5173端口。

### 🔍 根本原因
**重复启动导致的端口冲突**：

1. **Vite的端口分配机制**：
   - 首先尝试使用配置的端口5173
   - 如果5173被占用，自动递增到5174、5175等
   - 这是Vite防止冲突的默认行为

2. **重复启动的情况**：
   - 在终端A运行 `npm run dev` (占用5173)
   - 在终端B再次运行 `npm run dev` (自动使用5174)
   - 或者使用 `./start.sh` 时，前一个服务未正确停止

### 🛠️ 解决方案

#### 1. 检查正在运行的进程
```bash
# 查看Vite相关进程
ps aux | grep vite | grep -v grep

# 查看端口占用情况
netstat -tlnp | grep -E "(5173|5174)"
```

#### 2. 停止重复的进程
```bash
# 方法1: 杀死指定PID
kill [PID]

# 方法2: 杀死所有node进程 (谨慎使用)
pkill -f "vite"

# 方法3: 在对应终端按 Ctrl+C
```

#### 3. 重新启动服务
```bash
cd db-admin-web/frontend
npm run dev
```

## 🚀 预防措施

### 1. 启动前检查
```bash
# 启动前检查端口是否被占用
lsof -i :5173 || echo "端口5173可用"
```

### 2. 严格模式启动流程
```bash
# 方法1：使用严格模式一键启动脚本（推荐）
cd db-admin-web
./start.sh  # 现已支持严格模式，自动清理端口冲突

# 方法2：单独启动前端（严格模式）
cd db-admin-web/frontend
./start-strict.sh  # 新增的严格启动脚本

# 方法3：使用npm脚本
cd db-admin-web/frontend
npm run dev        # 现在会先检查端口
npm run dev-force  # 强制清理端口后启动
npm run check-port # 仅检查端口状态
npm run kill-port  # 仅清理端口
```

### 3. 创建启动检查脚本
```bash
#!/bin/bash
# check_and_start.sh

echo "🔍 检查端口占用情况..."
if lsof -i :5173 >/dev/null 2>&1; then
    echo "⚠️  端口5173已被占用，请先停止现有服务"
    echo "正在运行的进程："
    lsof -i :5173
    exit 1
else
    echo "✅ 端口5173可用，启动服务..."
    npm run dev
fi
```

## ⚠️ 注意事项

1. **不要同时在多个终端启动同一个服务**
2. **使用一键启动脚本 `./start.sh` 来避免冲突**
3. **停止服务时使用 Ctrl+C 而不是直接关闭终端**
4. **如果端口被占用，先检查是否有其他实例在运行**

## 🔧 严格模式技术实现

### 已实施的严格端口措施

1. **Vite配置强化** (`vite.config.js`)：
   ```javascript
   server: {
     port: 5173,
     strictPort: true, // 强制使用指定端口，如果被占用则报错退出
     // ...
   }
   ```

2. **NPM脚本增强** (`package.json`)：
   ```json
   {
     "scripts": {
       "check-port": "检查端口5173是否可用",
       "kill-port": "强制清理端口5173",
       "dev": "先检查端口再启动",
       "dev-force": "强制清理端口后启动"
     }
   }
   ```

3. **启动脚本强化**：
   - `start.sh`: 主启动脚本现支持端口检查和清理
   - `frontend/start-strict.sh`: 新增严格模式前端启动脚本

### 🚫 已禁用的备用端口机制
- ❌ 5174端口自动切换已禁用
- ❌ 5175、5176等备用端口已禁用
- ❌ Vite的端口递增机制已关闭

## 🎯 最佳实践

### 推荐的开发流程
```bash
# 1. 检查当前状态
netstat -tlnp | grep -E "(5173|5174|8081)"

# 2. 清理可能的残留进程
pkill -f "vite" 2>/dev/null

# 3. 使用一键启动

./start.sh
```

### 配置端口检查
在 `package.json` 中可以添加预启动检查：
```json
{
  "scripts": {
    "predev": "lsof -i :5173 && echo '端口被占用，请先停止现有服务' && exit 1 || echo '端口检查通过'",
    "dev": "vite"
  }
}
```
